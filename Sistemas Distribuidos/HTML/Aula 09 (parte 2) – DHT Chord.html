DHT Chord

Aula 09 (parte 2) · Sistemas Distribuídos · UFABC

1. Tabela de hash distribuída (DHT)

  • Sistema P2P estruturado: cada peer é cliente e servidor.
  • Criada em 2001 para achar um recurso com eficiência, em O(log N).
  • Dá escalabilidade de tamanho e particionamento (sharding).
  • Evita o ponto único de falha (SPoF).

Ideia: uma tabela de hash em um só servidor vira um SPoF se ele cair. A solução é distribuir a tabela por vários nós.

2. Construção do Chord

Três decisões: (1) definir um espaço comum de valores para nós e itens; (2) conectar os nós com poucos links, para minimizar saltos; (3) definir como designar itens aos nós.

  • Espaço de IDs: {0, 1, ..., 2M-1}, formando um anel módulo 2M.
  • Nós: cada nó recebe um número obtido por uma função de hash H.
  • Responsabilidade: cada nó cuida de um conjunto disjunto de IDs, de (ID do nó anterior + 1) até o seu. No exemplo com M=4 e nós 0, 2, 5, 6, 11: o nó 0 cuida de [12, 0], o nó 5 de [3, 5] e o nó 11 de [7, 11]. É o particionamento.
  • Sucessor: succ(x) é o primeiro nó, no sentido horário, com id ≥ x. Exemplo: succ(12) = 0, succ(1) = 2, succ(6) = 6.
  • Ligação: cada nó p aponta para succ(p+1). Invariante: um nó sempre tem conexão com seu sucessor.

3. Armazenar itens

Cada item <key, value> recebe o identificador k = H(key), com a mesma função H, e é guardado no sucessor de k. Exemplo dos slides: H('Seif') = 9, então o item fica no nó 11. H('Fatemeh') = 12 e H('Sarunas') = 14 vão para o nó 0. H('Cosmin') = 2 fica no nó 2. H('Tallat') = 4 vai para o nó 5.

Consistent hashing: técnica em que só O(m/N) pares chave-valor são transferidos quando nós entram ou saem (m chaves, N nós). O slide pergunta qual seria o problema de guardar o item no nó H(key) % N.

4. Busca

Para buscar a chave k, pergunta-se a qualquer nó, calcula-se H(k) e seguem-se os ponteiros de sucessor até achar. Exemplo: get('Seif') a partir do nó 2 passa pelos nós 2, 5, 6 e 11 e devolve "Stockholm". Só com sucessores, a busca é O(N).

Algoritmo findSuccessor

  • Se o id está em (predecessor, n], o nó n é a resposta.
  • Se o id está em (n, sucessor], o sucessor é a resposta.
  • Senão, encaminha a pergunta pelo anel (versão simples) ou ao nó mais próximo anterior ao id (com finger table).

put e get usam findSuccessor. Quando a resposta chega, o iniciador pede ao nó achado que guarde (store) ou devolva (retrieve) o valor. Notação: (a, b] exclui a e inclui b.

5. Buscas rápidas com finger table

Cada nó p aponta para succ(p+1), succ(p+2), succ(p+4), ..., succ(p+2M-1). Assim, FT_p[i] = succ(p + 2^(i-1)), para i = 1..M. A tabela tem M entradas, e o espaço guarda 2M chaves. Qualquer nó alcança outro em cerca de log2(N) saltos. Exemplo do slide: log2(1.000.000) é cerca de 20. Em implementações, normalmente M = 128.

closestPrecedingNode(id): percorre a finger table de i = M até 1 e devolve a primeira entrada que está no intervalo (n, id). Se nenhuma estiver, devolve o próprio n.

Exemplo: finger table do nó 0 (M=4, nós 0, 2, 5, 6, 11)
